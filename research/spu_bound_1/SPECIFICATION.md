# SPU-BOUND-1 specification

All variables are integers in [-2,2]. F1 uses independent a,b,c,d and xy; F2 uses a,b and x conjugate(x); F3 uses independent a,b,c,d and (xy) conjugate(y); F4 uses a,b with c=a,d=-b and xy, while its interval baseline deliberately forgets that relation. F5 uses q=a² on [-2,2], with corners and an interior minimum; xy components additionally exemplify multi-affine corner extrema. F6 uses the MATHSTATE-0 F3 point (2⁶³−1,0), y=2+√3 then its conjugate.

R1 propagates conventional Cartesian interval products/additions after every operation; no variable identity survives. R2 uses a small sparse polynomial map of exponent tuples to integer coefficients, combines like terms, and bounds each monomial with interval powers before adding intervals. This is sound but may lose cross-term dependencies. F4 substitutes the relation before expansion. F3 also compares an explicit factored norm identity, where its norm interval is calculated using square intervals. R3 uses independently coded integer-pair expansion and exhaustively evaluates all registered inputs. R4 checks selected explicit integer formulas with Z3; a separate 64-bit bit-vector check demonstrates wrapping, not Gen-1 refusal. Numeric bounds are inclusive and width is minimum signed two's-complement bits. All inputs and outputs are exact integers; SNORM is an unrelated tuple-normalization instruction.

The report records calculation and checking separately. Operation counts are source-level mathematical scalar operations under documented assumptions, not hardware instructions. Timings use perf_counter_ns for single descriptive runs; they are not benchmarks. Solver calls use an external 30-second timeout and a 25-second internal limit, 1 GiB virtual-memory limit, and no Python solver dependency. All local invocations use 30 seconds and 1 GiB. No float arithmetic in the mathematical model; timing values are integer nanoseconds.
