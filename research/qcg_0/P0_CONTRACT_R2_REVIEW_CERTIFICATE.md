**Reversal provenance:** psi(0)=r(1)=(2/3,1), not (0,0). ## Launcher remains a blocking defect

The new launcher protects against the previous existing-leaf overwrite problem: set-e, noclobber, pin precheck and exclusive mkdir are improvements. The following remaining issues are specific to the printed protocol:

- **Elapsed time is not deadline proof.** RC124/137 plus missing RUNNER_DONE plus elapsed≥59.9 can still be produced by OOM/external kill or a program exit at approximately that time, including before the actual deadline. Wall-clock date can also jump. A supervisor must durably attest that its own deadline fired; it must distinguish external kill/test failure/unavailable completion. Do not infer TIMEOUT from duration and exit status. Root contract's terminal timeout outcome uses exit124; persist the underlying raw exit separately if needed. `--kill-after=2 60` can leave the process alive past the declared 60-second hard wall; either keep that grace inside the frozen wall limit or explicitly obtain a changed budget/protocol, not an implicit extension.
- **PINS format:** `sha256sum -c` consumes checksum/path entries, not arbitrary “tool paths and versions”. Specify a real checksum-only file and a separate, pinned tool/version manifest/check. The snippet checks executability but does not compare the three versions as the prose claims. All implementation/source/reference identities still need a noncircular freeze.
- **Marker/count/post-check reliability:** exactly one marker must have a durable owner, and complete marker writing must precede any inference of success. The current `ls three_paths | wc -l` in a command substitution discards/mixes expected missing-file errors and pipeline status; replace it with explicit existence counting in the frozen protocol. This review does not claim that `set -e` inevitably aborts that particular substitution—the outer test can succeed despite ls's missing-file status. The important requirement is explicit handling, so after-pin evidence is always attempted and any inability to write evidence becomes unavailable/failed rather than assumed complete.
- **Output-cap enforcement includes external logs:** a runner cannot by itself guarantee a cap on arbitrary redirected stderr/stdout/provenance after it is killed. Specify enforcement or the exact external owner. The global M/A/S/D/K attempt-budget event set is now explicit and correctly includes conformance, mutants, refusals and timing repeats; oracles remain within the same external memory/wall/output envelope.

These are protocol fixes, not a request to launch anything. No shell simulation, timeout experiment or P0 code was run in this review.
