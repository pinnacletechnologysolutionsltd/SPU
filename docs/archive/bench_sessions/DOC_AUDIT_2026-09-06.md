# Documentation & Repository Audit — 2026-09-06

**Status:** rev 2 — 2026-09-06, after external review and operator direction.
Findings only; no document has been corrected yet.

## Revision history

**rev 2.** External review found the headline P1 count of 49 to be an
**overcount produced by regex granularity, not 49 independent unsupported
claims** — verified and accepted. Three mechanisms, all confirmed at source:
multi-line negations (`...no` / `regression risk to anything currently
silicon-proven`), per-row counting of single tables, and citations sitting
just outside an arbitrary ±10-line window. `tools/doc_audit.py` was fixed and
the corpus re-measured. A contradiction pass was added at the operator's
direction. **The verdict changed with it:** this repository does not have a
culture of fabricating silicon results; it has a **pointer hygiene** problem.
**Method:** mechanical sweeps via `tools/doc_audit.py`, plus judgement-level
review of the top-level documents. Every mechanical finding is reproducible.

## How to reproduce

```bash
python3 tools/doc_audit.py --actual-pass 226      # all checks
python3 tools/doc_audit.py --check claims         # one class
python3 tools/doc_audit.py --check contra         # superseded-status pass
python3 tools/doc_audit.py --json                 # machine-readable
```

### Scope model for the claims check (rev 2)

A claim counts as **covered** when a `hardware_evidence` reference appears in
either its own paragraph/table block, **or** the opening paragraph of its
section — the latter being the only thing that counts as declaring a shared
evidence source. **Whole-section scope was considered and rejected** as too
generous: it would bless unrelated claims in a long section. Negation
detection spans the current line and the one before it, because 80-column
prose wraps. Consecutive rows of one table are **one grouped finding**.

`--actual-pass 226` is today's measured suite total (`bash tools/verify_repo.sh`,
2026-09-06). Re-measure before quoting it.

## The structural finding, which explains most of the rest

`tools/verify_repo.sh`'s evidence-citation gate is **diff-scoped by design** —
the 2026-08-19 governance rewrite made it check only lines changed since HEAD,
so that pre-existing documents need not be cleared to pass. That was a
deliberate and reasonable decision.

**Its consequence was never stated: the existing corpus has never been
audited by it.** Everything below in the "uncited claims" class predates the
gate or was never touched by a commit that would trigger it. The gate is not
broken; it has simply never looked here.

## P3 — structural, needs a decision rather than a fix

**105 of 212 tracked markdown files are linked from no other tracked markdown
file.** Half the documentation is unreachable by navigation. Orphaned is not
automatically wrong — bench procedures and specs are legitimately standalone,
and some are reached from code comments or handovers. But at 50% there is no
navigable structure, and it is the documentation analogue of the
zero-instantiation problem `tools/rtl_instantiation_audit.py` was built for on
the RTL side.

**The causal link, from review:** orphaned documents *never get evaluated
during a pivot*. When SOM was shelved on 2026-09-03, orphaned SOM specs
carried on asserting active status because nothing in the navigation tree
pointed at them. **The orphan problem and the staleness problem are the same
problem**, which is why P1b's hits cluster where they do.

**Remediation is a TRIAGE INVENTORY, not bulk deletion** (operator direction,
rev 2). Three buckets:

1. **Active** — link from an index or topic map.
2. **Historical / shelved** — move under `docs/archive/`, which the tool
   already skips. Must remain **discoverable**, not deleted: this project
   keeps negative results by policy (AGENTS.md).
3. **Delete** — only what is actually wrong, such as links to the
   `rm -rf`'d `spu_strategy/` targets that cannot be restored.

## What this audit did NOT check

Stated so the gaps are known rather than assumed covered:

- **Prose accuracy.** Only claim *form* is checked, never whether a cited
  section actually supports the claim made.
- **Code/doc agreement.** Whether a documented port, opcode or file path still
  matches the RTL.
- **Cross-document contradiction.** Two docs asserting incompatible things
  will both pass every check here.
- **The `spu_strategy/` corpus**, which is gitignored and so invisible to
  `git ls-files`.
- **Blog and papers**, excluded from the claims sweep.
  `docs/blog/zero_drift_phi_arithmetic.md` is separately known to claim a
  non-existent arXiv paper, cite `github.com/spu13` which never existed, quote
  an unsourced 200 MHz figure, and assert "silicon-proven SOM classification"
  post-shelving (09-05 §6 recommended cutting it; no decision taken).
