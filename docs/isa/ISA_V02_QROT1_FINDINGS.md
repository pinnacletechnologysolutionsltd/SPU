## Implemented operation

`QROT QRn` (both VMs): `n = R1 mod 13`; each component `x` becomes `x·(2+√3)` by exact `Q(√3)` multiplication, then the common minimum component is subtracted (`normalize`, exact `Q(√3)` ordering). `R2` is ignored (assembler encodes `QROT QRd [, Rs]` into `R2`). The Python VM then sets the φ-plane tag to `PHI_UNTAGGED`; the C++ VM has no tags. A component that carries a Pell tag (from `LD R,1,0` or `ROT`, moved by `QLOAD`) is instead **replaced** by `PELL_ORBIT[(step+1) mod 8]` regardless of its stored value. Sources: `software/spu_vm.py` (`RationalSurd.rotate_phi`, `QuadrayVector.rotate`, `OPCODES["QROT"]` branch), `software/vm/spu_vm.cpp` (`rotate_phi`, `QuadrayVector::rotate`, `case 0x11`), `software/tools/spu13_asm.py` (`QROT` encoding). `ROT` has the same in-place single-step shape and also ignores `Rs`/`n`.

## Results (u = 2+√3)

Proven (bilinearity / multiplicativity): `Q(u·v) = u²·Q(v)`; `B_Q(u·v,u·w) = u²·B_Q(v,w)`; spread `N/D` invariant where defined, i.e. nondegenerate (`D ≠ 0`; `N` and `D` each scale by `u⁴` regardless); `N_{Q(√3)/Q}(Q(v))` invariant because `N(u)=1`; the map is `Q(√3)`-scalar multiplication on gauge classes, hence a similarity of ratio `u²` (≈13.93 in the real embedding), a bijection with inverse `×(2−√3)`, **not** an isometry. `rot(v + c·(1,1,1,1)) = rot(v)` literally follows from `normalize(x + t·1) = normalize(x)` for exact minimum subtraction (no ordering or sign assumption on `u` is needed). `rot` is not literally additive: `normalize` subtracts a data-dependent minimum.

Sampled only (310 vectors, 1800 pairs; scenario programs): the above identities in the VMs' actual arithmetic; FIELD-0 witness `(3,1,0,0)`: Q 24 → `(168,96) = 24·(7+4√3)`, matching `test_field0_intrinsic_metric.py`; both VMs agree on every non-overflow scenario.

Pell-tag path (identical in both VMs): steps 0–6 equal `u·value`; `r⁷ = (5042,2911)` → `(1,0)` (mantissa wrap: Q 152530581+88063572√3 → 3, not `u²·Q`); mixed steps scale components differently, so it is not a similarity. The octave count is dropped by `normalize`. **Scope of the tag statements:** that a tagged component holds `PELL_ORBIT[step mod 8]` is established by construction for the audited paths only: the `LD` seed of exactly `(1,0)` (`spu_vm.py:1383-1387`; `spu_vm.cpp:603`) and `ROT` (`rotate_phi`, `spu_vm.py:262-291`; `spu_vm.cpp:660`). Transfer paths into Quadray registers (`QLOAD`, `QLDI`, vector operations) were not audited exhaustively in either VM. No counterexample was found by the author or the review; universality remains unproven.

Bounded profile: Python is unbounded. C++ checks `int32`: starting from `(100,0,0,0)`, the 14th `QROT` is refused (atomic restore of regs/QRs/PC/counters, halt, rc 1). For 10–13 rotations all `QROT`s succeed and the process then aborts uncaught (rc 134) in the end-of-run register display. The independent review captured a terminate stack for the 10-rotation case: `checked_i32` → `RationalSurd::operator*` (`spu_vm.cpp:70`) → `QuadrayVector::quadrance()` (`:193`) → `SPUCore::qreg_str()` (`:558`) → `dump_registers()` (`:1076`) → `main()` (`:1186`). That trace is the review's result (obtained with a temporary debug build and an `LD_PRELOAD` terminate handler); the author did not reproduce it and relied on output position.

Incorrect source comments (not edited): `spu_vm.py` (`QuadrayVector.rotate` docstring) and `software/common/include/spu_quadray.h` (header and `pell_rotate`) say quadrance is preserved.

## Recommended normative definition (ratification HOLD)

`QROT QRn` replaces `QR[n]` with `normalize(u·QR[n])`, `u = 2+√3` (a similarity of ratio `u²`; preserves spread, gauge equivalence and the Pell norm of the quadrance; not quadrance). HOLD: the Pell-tag/octave path; bounded-profile refusal and the display-path crash; whether `QROT`/`ROT` keep the historical `Rd, Rs, n` form.

Applied: spread preservation is restricted to defined (`D ≠ 0`) spreads. A minimum tie has equal field values, so which tied component is chosen does not change the normalized output.
2. **C++ abort.** Review result: the stack above places the abort in end-of-run display formatting, not in an executed instruction. This settles the earlier output-position inference; provenance is the review's.
3. **Pell tags.** Review result: universality across every constructor and transfer path is unproven; no counterexample reproduced. Applied: the tag statements are narrowed to the audited paths (see Results).

These mutation results are the review's, not reproduced by the author. Limits: no exhaustive mutation campaign; post-`QROT` snapshots do not establish full architectural-state equality or later-instruction behavior; the repro cannot detect every possible VM divergence.
5. **O6 and D1 questions** are answered in `ISA_V02_O6_FINDINGS.md` (scope and limits section): the O6 `MISSING_IN_CLAIMED_PROFILE` rule rests on the assembler header comment; the extractor misses relative-index decoders (verified: `spu13_surd_exec.v:59`); D1 rows are source/configuration inferences with no synthesis or elaboration.

## Limitations

- Opcode extraction is regex-based and non-exhaustive (see `ISA_V02_O6_FINDINGS.md`).
- Audits cover in-tree tops and testbenches only; external configurations are not evaluated.
- **SPU-4 `QROT` is a different operation (resolved by independent review, checked at `f61fee0`).** `spu4_sequencer.v:138` decodes `QROT` as `8'h45` (ISA-A: `0x11`; the same arm also starts `QADD` `8'h40`). `spu4_euclidean_alu.v` computes a Q8.8 fixed-point circulant transform of B, C, D with F/G/H coefficients (`B'=F·B+H·C+G·D`, with overflow fold and `henosis_pulse`), A passed separately. The shared mnemonic does not imply shared semantics. The ledger's SPU-4 `QROT` silicon entries (around §3.2j) exercise that circulant ALU with specific fixtures; they are **not** evidence for the ISA-A operation. The O6 inventory is SPU-13/ISA-A only; SPU-4 must be inventoried as its own profile, not merged. Not extended here.
- The SPU-13 core RTL has no `QROT` decode in the O6 inventory; no SPU-13 RTL comparison was made.
- Identities `b063280`, `2cbfa6f`, `19d652a`, `f61fee0`, `6deab30`, `eaabd9f` are distinct; conclusions apply to the identity stated. The reviewed identity for AR1 is `eaabd9f`.
- Nothing here is a silicon claim. The ledger's `QROT` entries concern the SPU-4 implementation; none attests the ISA-A VM semantics characterized here.
